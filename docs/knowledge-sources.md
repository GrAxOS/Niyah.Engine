# Canonical Knowledge Sources

The canonical graph only promotes externally verifiable technical knowledge to `asserted` status when the source is explicit and stable.

## PostgreSQL

- PostgreSQL official documentation: database SQL, constraints, indexes, recursive queries, JSON/JSONB and full-text search.
- Source: https://www.postgresql.org/docs/current/

## JSON Schema

- JSON Schema Draft 2020-12 specification.
- Source: https://json-schema.org/draft/2020-12/json-schema-core.html

## Supabase

- JSON/JSONB data modeling guidance.
- Semantic search with pgvector.
- Hybrid search using full-text search, vector retrieval and Reciprocal Rank Fusion.
- Row Level Security.
- Structured and unstructured metadata guidance.
- Vector index guidance for HNSW and IVFFlat.

## Important evidence rule

A URL being present is not proof by itself. Every evidence record contains a content hash and observed timestamp. Hash values in fixture examples are placeholders until generated from the retrieved source bytes; they must not be treated as cryptographic verification of the live source.

## Claim status

`asserted`  = source-backed technical statement.
`inferred`  = deterministic derivation from asserted facts.
`candidate` = retrieval proposal not yet accepted as graph truth.
`rejected`  = failed validation.
`deprecated` = previously valid graph object retained for history.
